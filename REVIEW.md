# REVIEW.md

List every defect you found in the starter `app/main.py` (helpers and endpoints). For each one:

| # | Where (function / line) | What is wrong | How you'd notice it (test, input, or symptom) | How you fixed it |
|---|---|---|---|---|
| 1 | `health` (lines 72-74) | Always returns `{"status": "ok"}` without verifying database connectivity. Contract requires 503 when MongoDB is unreachable. | Stop MongoDB service or misconfigure `MONGO_URI`; `GET /health` returns 200 OK instead of 503 Service Unavailable. | Added `client.admin.command('ping')` inside a try-catch block and raised `HTTPException(503, "Database unavailable")` on failure. |
| 2 | Startup lifecycle | No indexes created at application startup. The problem statement mandates idempotent index creation at startup. | Concurrency races cause duplicate records; MongoDB explain plans report `COLLSCAN` with degraded query latency on large datasets. | Implemented a FastAPI `lifespan` context manager that calls `init_indexes()` to idempotently create unique and lookup indexes. |
| 3 | `compute_late_minutes` (lines 33-37) | Checked `minutes > 10` after integer floor division (`diff / 60`), improperly applying the 10:00 grace threshold. For punch-in at 09:40:01 on a 09:30 shift (601 seconds), `int(601/60) = 10`, and `10 > 10` evaluated to `False` (0 minutes). Also, `replace(hour=h, minute=m)` on punch-in date failed for overnight shifts across midnight. | Test with punch-in `09:40:01` on shift `09:30`; returned `0` instead of `10`. Test overnight shift punch-in at 01:00 AM; replaced date to current day rather than shift start day. | Checked `(punch_in - shift_start).total_seconds() > 600` strictly, floored whole elapsed minutes from `shift_start`, and anchored shift start to the shift's attendance date. |
| 4 | `compute_work_hours` (lines 40-41) | Used Python's built-in `round()`, which performs banker's rounding (round-half-to-even) rather than round-half-up specified in Rule R4. | Test duration of 2.675 hours; `round(2.675, 2)` produced `2.67` instead of `2.68`. | Used `decimal.Decimal` with `ROUND_HALF_UP` (`Decimal.quantize(Decimal("0.01"), rounding=ROUND_HALF_UP)`). |
| 5 | `compute_overtime` (lines 44-48) | Missing 30-minute minimum qualification threshold (Rule R3). Any positive minutes were awarded immediately. Also failed to increment calendar day for overnight shift ends across midnight. | Punch out at 18:45 on 18:30 shift returned 15 minutes overtime instead of 0. Overnight shift punch-out compared against same-day date. | Set overnight shift end to `date + 1 day`, and returned `diff_minutes` only if `diff_minutes >= 30`, otherwise `0`. |
| 6 | Punch instant handling (lines 102-103) | Sub-second milliseconds were preserved rather than truncated to whole seconds (Rule R1). | Punch at `09:40:00.900` preserved `.900` ms, resulting in non-standard epoch values and potential calculation drift. | Added `truncate_epoch_to_seconds(ms)` via `(ms // 1000) * 1000` before constructing datetimes and calculations. |
| 7 | Datetime timezone handling (lines 82, 102) | Used naive `datetime.now()` and `datetime.fromtimestamp()`. When stored in MongoDB or serialized, timestamps drifted by the server's local UTC offset. | On servers with non-UTC local timezones, stored BSON datetimes and converted epoch values diverged from UTC. | Configured `tz_aware=True` on `MongoClient` and enforced timezone-aware UTC datetimes (`datetime.now(timezone.utc)` and `tz=timezone.utc`). |
| 8 | `create_employee` (lines 79-83) | Check-then-insert pattern (`find_one` followed by `insert_one`) created a race condition under concurrent requests. | Concurrent `POST /employees` requests with identical `emp_code` both succeeded or threw uncaught database errors. | Backed by unique index on `employees.emp_code`, caught `DuplicateKeyError`, and returned HTTP 409 Conflict. |
| 9 | `EmployeeIn` validation (lines 53-60) | Missing schema constraints: lacked `emp_code` regex (`^EMP\d{4,6}$`), email regex, string length bounds, and permitted `shift_start == shift_end`. | Sending invalid emp code `"TEST"`, invalid email, or `shift_start == shift_end` returned 201 Created instead of 422 Unprocessable Entity. | Implemented Pydantic `Field` validations and model validators for `emp_code`, email, date format, and `shift_start != shift_end`. |
| 10 | `create_employee` response (lines 82-85) | `created_at` in the returned response was a Python datetime serialized as an ISO string instead of epoch milliseconds integer (`EpochMillis`). | `res.json()["created_at"]` returned `"2026-01-05T04:30:00"` instead of integer epoch milliseconds (e.g., `1767587400000`). | Converted `created_at` datetime to epoch milliseconds integer in the response formatter. |
| 11 | `list_employees` pagination (line 93) | Calculated `skip = page * page_size`. For page 1, skipped `1 * 20 = 20` documents, omitting the first page of results. | Requesting `GET /employees?page=1` returned items starting from index 20, missing items 0-19. | Corrected 1-based pagination offset to `skip = (page - 1) * page_size`. |
| 12 | `list_employees` total count (line 94) | `total` ran `count_documents({})`, returning total collection count instead of the filtered count matching query `q`. | `GET /employees?department=HR` returned HR items, but `total` reported company-wide employee count. | Updated total count to `db.employees.count_documents(q)`. |
| 13 | `list_employees` sorting (line 95) | Did not specify a sort order on `db.employees.find(q)`. Contract requires sorting by `emp_code` ascending. | Returned documents in arbitrary MongoDB natural insertion order. | Added `.sort("emp_code", pymongo.ASCENDING)` to cursor. |
| 14 | `punch_in` concurrency race (lines 104-118) | Check-then-insert race condition (`find_one` then `insert_one`) allowed duplicate punch-ins for the same employee and date under concurrency. | Concurrent `POST /attendance/punch-in` requests created duplicate records for the same employee and date. | Created unique compound index on `(emp_code, date)`, caught `DuplicateKeyError`, and returned HTTP 409 Conflict. |
| 15 | `punch_in` employee lookup (lines 101-102) | Missing existence check for employee (`emp = db.employees.find_one(...)`). | Punch-in with non-existent `emp_code` caused `TypeError: 'NoneType' object is not subscriptable`, yielding 500 Internal Server Error. | Added check: if `emp is None`, raise `HTTPException(404, "Employee not found")`. |
| 16 | `punch_in` validation (lines 63-67) | Allowed invalid status values (such as `ABSENT` or `LEAVE`) and accepted invalid or seconds-looking epoch timestamps. | Sending `status: "LEAVE"` or `punched_at: 1700000000` (seconds) was accepted and created invalid records. | Constrained `status` to `Literal["PRESENT", "WFH", "ON_DUTY"]` and bounded `punched_at` to `[100000000000, 4102444800000]`. |
| 17 | `punch_in` response contract (lines 119-121) | Injected `"id": str(res.inserted_id)` and left `punch_in` as datetime. Contract explicitly excludes `_id`/`id` and requires epoch milliseconds. | Returned payload contained `"id"` field and `punch_in` as ISO string. | Formatted response via `format_attendance_doc`: excluded `_id`/`id` and converted datetimes to epoch milliseconds. |
| 18 | `list_attendance` memory & sorting (lines 144-150) | Loaded all matching documents into memory via `list(db.attendance_logs.find(q))`, sorting and slicing in Python. | On a dataset of ~100,000 documents, caused severe memory consumption, slow responses, and potential process crashes. | Pushed sorting and pagination directly into MongoDB with index-backed `.sort([("date", -1), ("emp_code", 1)]).skip(skip).limit(page_size)`. |
| 19 | `list_attendance` date range validation (lines 136-141) | Did not validate `date_from <= date_to`. Contract specifies 422 if `date_from > date_to`. | Querying `GET /attendance?date_from=2026-07-10&date_to=2026-07-01` returned 200 with empty items instead of 422. | Added validation raising `HTTPException(422, "date_from must be <= date_to")`. |
| 20 | Pagination query parameter bounds | `page` and `page_size` lacked boundary constraints. Contract specifies `page >= 1`, `1 <= page_size <= 100`. | Request with `page_size=1000` or `page=0` was executed instead of returning 422. | Added FastAPI `Query(ge=1)` and `Query(ge=1, le=100)` to query parameters. |

## Items Examined and Decided NOT to be Defects

1. **`emp_code` as business identifier instead of MongoDB `_id`**: The customer-facing business logic explicitly uses `emp_code` (e.g. `EMP0001`) as the unique natural identifier across all endpoints and relations. MongoDB's `_id` is purely internal and correctly excluded from API contracts.
2. **`history` initialized to empty list `[]` on punch-in**: Punch-in and punch-out are original operational events. Per specification, `history` is strictly an audit trail for manual corrections (`PATCH /attendance/{emp_code}/{date}`) and must remain empty until an administrative regularization occurs.
